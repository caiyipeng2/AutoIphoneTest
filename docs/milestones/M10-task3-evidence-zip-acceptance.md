# M10 Task 3 - ZIP64 evidence publisher acceptance

## Scope

This slice adds the streaming ZIP64 writer that consumes the previously approved deterministic manifest. It publishes one archive atomically; independent extraction and manifest hash verification remain a separate slice.

## Delivered behavior

- Pins `archiver` `8.0.0` and `@types/archiver` `8.0.0` for the reports package with a minimal lockfile change.
- Forces ZIP64 headers even for small archives and writes `manifest.json` plus the manifest-bound physical entries from `Readable` or async-iterable sources.
- Validates canonical relative paths, manifest/physical-entry count, association IDs, duplicate entries, and the reserved `manifest.json` name before creating the output directory.
- Writes to a sibling `.partial-<attempt>-<uuid>` file, listens for archive/output/source errors, removes the partial file on failure, hashes the closed archive, and atomically renames it to the final path.
- Uses a fixed archive entry timestamp to keep generated bytes reproducible for identical input streams.
